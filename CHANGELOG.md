# Changelog

and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Security

- **platform-pgcommon v2.0.0 → v2.0.1.** It applies the transaction timeouts inside `WithConn`'s PgBouncer wrapping transaction and builds with go1.26.9. No API change.
- **`rest-call` and `sql-query` cannot be sent to another host.** An alias `pathTemplate` or `path` must start with `/` (`aliasconfig.Validate`). Every request URL must keep the alias `baseURL`'s scheme and host, with no userinfo (`shared.NewInternalRequest`); anything else is `ErrValidation`.
- **`rest-call` path and query parameters cannot change the request.** A path parameter that renders as `""`, `.` or `..` is `ErrValidation`. Placeholders in a template's query string are query-escaped, so a value cannot add a parameter. `queryParams` cannot override a key that the alias's `pathTemplate` query string already sets (`ErrValidation`).
- **`x-departments` cannot be forged.** An empty department list, or a department that is empty or contains `,`, CR or LF, is `ErrMissingInternalAuth` (permanent), raised before any request.
- **Internal calls use HTTP/1.1 only.** `rest-call` and `sql-query` no longer use HTTP/2, so Go's HTTP/2 client cannot replay a non-idempotent request after a stream reset. A nil client's transport, or a caller's `*http.Transport`, is cloned with HTTP/2 off (the caller's own transport is untouched). Any other `RoundTripper` is used as-is.
- **Release tags are verified exactly.** `verify-release-tag.sh` looks for the tag among all tags on HEAD, so two tags on one commit no longer fail the release. It also requires the tagged commit to be on `origin/main`.
- **Document-ref resolution checks the exact object key.** `Lookup`, `Open`, `Read` and `Delete` require the record's object key to equal `<prefix><tenant>/<uuid>` for the ref's own ID, instead of only checking that it sits under the tenant's prefix. A tampered record pointing at another of the tenant's objects is `ErrIntegrityViolation`.
- **The runbook's worker ACL lists every command the store uses.** The Lua scripts and `CheckDurability` also run `EXISTS`, `HMGET`, `HSET`, `TIME` and `PEXPIREAT`; the runbook now gives one exact `ACL SETUSER` line. An integration test creates a user from that line and runs every store operation as it. Previously a worker configured as documented failed every write.
- **Gmail display names cannot add recipients.** `send-email` (Gmail) quotes and encodes the sender and receiver display names, so a name containing `,`, `<`, `>` or quotes can no longer add recipients or change the address.
- **Email providers are called over HTTP/1.1 only.** Go's HTTP/2 client silently replays a request body when the server resets the stream with `PROTOCOL_ERROR` — a reset that does not prove the request went unprocessed — so a send could be delivered twice and reported once (`shared.ProviderHTTPClient`).
- **SendGrid could send one email twice and drop another.** `sendgrid.Client.SendWithContext` writes each message body onto the client before sending, and the client is cached and shared by concurrent calls with the same credentials: two concurrent sends could swap bodies — one recipient got the other's message twice, the other's was never sent yet reported `accepted` (with the wrong message ID and send intent). The adapter now builds every request itself (`POST /v3/mail/send`) with no shared mutable state; a 50-way concurrent test checks every recipient gets exactly their own message.
- **SSRF through tenant credentials.** A Google service-account key carries its own `token_uri`, which the Google libraries POST to and quote the reply from in errors: a tenant could aim the worker at internal hosts. `gcp-gcs`, `google-drive` and `google-workspace` now accept only Google's token endpoint and universe (`shared.ValidateGoogleServiceAccountKey`). The Azure account and container names must match Azure's naming rules, and the `microsoft-365` `tenantId` must be a GUID or domain, since each goes into a URL.
- **Provider HTTP clients never follow redirects** (`shared.ProviderHTTPClient`, also under the Gmail, Graph and Drive OAuth transports and the GCS client): a redirect would re-send the request and its bearer token or API key to another host. They have their own transports (closed when the cache retires the client) and a 2-minute ceiling; SendGrid error bodies are read up to 64 KiB.
- **Every GitHub Action is pinned to a full commit SHA** (with the exact version as a comment: `actions/checkout@3d3c42e… # v7.0.1`, and likewise for `cache`, `setup-go`, `upload-artifact`, `download-artifact`, `github-script`, `trivy-action`, `codeql-action/upload-sarif`) instead of a movable tag, so a retagged or compromised action cannot run with this repository's token and secrets. `validate-quality.yml` now fails on any unpinned third-party action.
- **SES sends are no longer retried by the AWS SDK.** The SDK's standard retryer resent `SendEmail` up to 3 times on throttling, 5xx and transient errors — duplicate emails whenever the first attempt had in fact been accepted. The SES client is now built with `aws.NopRetryer`; verified against a test server (3 requests before, 1 after).
- **`rest-call`/`sql-query` no longer follow redirects.** Go re-sends custom headers on a redirect, so an internal service answering `3xx` to another host received `x-internal-token` and `x-departments`. The caller's `http.Client` is now copied with redirects disabled; a `3xx` is `ErrUpstream`.
- **Email address fields must be one bare address.** `receiverEmail: "a@x.com, attacker@y.com"` added a recipient on Gmail's raw-MIME path; `senderEmail`/`receiverEmail` are now checked with `net/mail.ParseAddress` before any provider is called.
- **S3 and SES clients no longer read the worker's AWS environment.** `config.LoadDefaultConfig` pulled the worker's `AWS_REGION`, `AWS_ENDPOINT_URL` and shared config into every tenant's client; clients are now built from the tenant's credentials and region only.
- **Drive search queries use Drive's single-quoted literals** (backslash and quote escaped) instead of Go's `%q`.
- **`rest-call` drops `Set-Cookie`** from the headers it returns to the workflow.
- Go 1.26.9 and `golang.org/x/net` v0.60.0 (reachable `govulncheck` findings GO-2026-6599, GO-2026-6600, GO-2026-6603, GO-2026-6605, GO-2026-6607, GO-2026-6608, GO-2026-6610, GO-2026-6611, GO-2026-6612, GO-2026-6613, GO-2026-6617 in `net/http`, `html/template`, `net/textproto`, `crypto/tls` and `x/net`). `x/crypto`, `x/mod`, `x/sync`, `x/sys` and `x/text` move with `x/net`.

### Changed

- **Breaking: removed the class sentinels.** `connectors.ErrTransient` and `connectors.ErrPermanent` are gone, along with `shared.ErrTransient`, `shared.ErrPermanent` and `ClassifiedError.Is`. `errors.Is` could disagree with `ClassOf`, for example on invalid input that wraps a transient cause. Use `connectors.ClassOf`, `IsTransient`, `IsPermanent` or `DecideRetry` instead.
- **Breaking: JSON numbers are decoded exactly.** `rest-call` and `sql-query` decode JSON numbers as `json.Number` instead of `float64`, so integers above 2^53 keep every digit. `shared.StringField` and `StringSliceField` accept `json.Number`.
- **Breaking: two `shared` helpers changed.** `shared.ApplyQueryParams` now returns an error, and `shared.DepartmentsFromContext` reports ok only for a non-empty, valid list.
- **`rest-call` marks cut-off error bodies.** On a status of 300 or above, the output adds `bodyTruncated: true` when the error body was over 10 MiB (cut to its first 10 MiB) or ended early (what arrived is kept). Such a body is returned as a string.
- **Breaking: document-ref `Put` is idempotent** (`valkeystore.Store.Put` and `docref.MemoryStore.Put`). A retry that finds exactly the same ref succeeds and returns the original timestamps; WAITAOF is still required. A different existing ref is still `docref.ErrExists`.
- **Breaking: `valkeystore.CheckDurability` checks replicas on a Valkey Cluster.** `appendonly`, `appendfsync` and `maxmemory-policy` are checked on every replica as well as every master, and errors name the node's role and address.
- **Added `valkeystore.Options.WaitReplicas`.** It requires replica AOF acknowledgement (`WAITAOF 1 n`) before `Put` returns. The default of 0 keeps today's behaviour, which confirms the primary's AOF only.
- **More failover replies are transient.** `READONLY`, `MASTERDOWN` and `NOREPLICAS` are `docref.ErrUnavailable`. The slot map is reloaded only for topology replies, and only on a cluster client.
- **Breaking: `sendintent.Store.Reserve` takes an attempt and a token.** The new signature is `Reserve(ctx, tenantID, messageKey, resendFrom int, token string)` instead of `resend bool`. The `Store` interface adds `Get(ctx, tenantID, messageKey)`, and `MemoryStore.Get` now takes a ctx and returns an error. `Intent.ReservationToken` and `DuplicateRequestError.Attempts` are added.
- **Breaking: `send-email` `resend: true` requires `resendAttempt: <n>`.** `n` is the intent's current number of attempts. The resend goes ahead only while that attempt is still current and not pending, so a redelivered resend job is a duplicate and sends nothing.
- **Breaking: a duplicate of an accepted email succeeds.** `send-email` returns no error and `{sent:false, duplicate:true, status:"accepted", providerMessageId, deliveryOutcome:"accepted"}`. Other duplicates still fail with `DuplicateRequestError`, and their output now carries `status`, `attempts` and `deliveryOutcome`.
- **Per-provider attachment limits.** `send-email` enforces them through the new `sendemail.AttachmentLimiter`: SendGrid 20 MiB, Microsoft 365 3 MiB (inline `sendMail`), Gmail and SES 25 MiB.
- **Migration `000002` adds `connector_send_intents.reservation_token`.**
- **`SendError` exposes one class.** `SendError.Unwrap` no longer exposes classifiers or class sentinels from its cause, so the error's own `ErrorClass` is the only class.
- **Drive adopts a same-name file placed by hand.** The first upload of a name updates and tags the oldest untagged same-name file in the folder instead of creating a second file. With no registry row, fetch and delete by name use that same file and never a file tagged by another document. Delete always claims the registry row, inserting one if needed, so it cannot race an upload that is adopting the file.
- **Storage delete of a missing object succeeds.** On `aws-s3`, `azure-blob` and `gcp-gcs` it is now idempotent; it used to be a permanent upstream error.
- **Database errors carry a retry class.** Both PostgreSQL stores (the document registry and send intents) mark these transient: serialization failure, deadlock, lock not available, query canceled, operator intervention, connection exception, insufficient resources, and (in the registry) claim contention. A closed pool is unknown.
- **A stale pending send intent can be resent.** An explicit resend (`resendAttempt` naming its attempt) can take over a `pending` intent once it has been unchanged for `sendintent.StalePendingAfter` (15 minutes), so a worker that stopped mid-send no longer needs a manual SQL fix. `sendintent.MemoryStore.SetClock` is added for tests.
- **Coverage gate raised to 98%; measured coverage 99.96%** (2,309 of 2,310 statements, up from 85.6%). New tests cover: the real Drive v3 API calls and every registry and Drive failure path in `storage/googledrive`; `storage/gocloud`'s blob-driver failures and Azure/GCS construction (including the never-follow-redirects GCS client); `valkeystore` against a scripted RESP server (timeouts, OOM, WAITAOF refusal, cluster MOVED, `CheckDurability` per node); `docref` fault injection and size-less streams; the PostgreSQL stores' error paths in isolated throwaway schemas; every send-email provider's token, request and response paths; and the remaining branches of `shared` and the smaller connectors. Production changes made only for testability, with behaviour unchanged: the SDK constructors in gocloud are package variables that tests can replace (their errors are still handled); the duplicate-type panic in `connectors.New` and `registry.All` moved into an `indexByType` helper; and error branches that cannot occur were removed: Gmail MIME writes to a `bytes.Buffer` (`buildRawMIME` no longer returns an error), Graph's `json.Marshal` of a string-only request, and `fs.Sub` of the constant `migrations` directory. The one uncovered statement is the send-email total-attachment guard, kept as defence in depth even though `docref` already enforces the budget. The compose PostgreSQL runs with `max_connections=300`, because all suites in one `go test ./...` exceed the default of 100.
- **`.github` aligned with iam-user-profile's, scoped to a library.** The pull request template adds the migration and registry-contract change types, per-suite test items (`make test-unit` / `test-postgres` / `test-integration` / `test-ci`), `make fmt-check` and `make arch-lint`, a pgcommon-only check, and Registry contract, Database / Migrations and ARCHITECTURE.md / runbook sections. The bug report adds Environment and Affected area sections and a log block; the feature request adds Affected areas and Contract impact. CODEOWNERS covers `.github/scripts/`, `pkg/registry/`, both `sqlstore/migrations/` directories (with the platform team) and the lint and architecture configuration. user-profile's image, Helm deploy gate, Cosign, metrics, Swagger, event-schema and schema-freeze automation do not apply to a library and were not brought over.
- **Breaking:** `sendintent.Store.Record` takes the attempt number (`Record(ctx, id, attempt, status, …)`) and writes only while that attempt is the intent's current pending one (`sendintent.ErrStaleRecord` otherwise); `s3content.Store.Check` takes the document key prefix (`Check(ctx, "docrefs/")`).
- **All database access goes through platform-pgcommon only.** The document registry and send-intent stores (and every PostgreSQL test) use pgcommon's own types — `pgcommon.Conn`, `Row`, `Tx`, `TxOptions`, `ErrNoRows` — with `Pool.WithConn`, `pgcommon.RunInTx` and `pgcommon/migrate`, instead of importing `pgx`/`pgxpool` directly; the PostgreSQL deployment tests no longer open raw `pgx` connections. The README wiring configures the pool with `pgcommon.ConfigFromEnv` and migrations with `pgcommon.MigrationDSNFromEnv`. Enforced by `.go-arch-lint.yml` (pgx is no longer a permitted vendor) and a golangci `depguard` rule (`pgcommon-only`) covering tests.
- **Breaking: the module path is now `github.com/BCBP-SOLUTIONS-FZC-LLC/workflow-connectors/v2`.** `v1.0.0` is published and this release changes exported API (below and in the entries that follow), so under semantic versioning it is v2.0.0, and Go requires the `/v2` suffix for it. Consumers change their imports from `…/workflow-connectors/pkg/…` to `…/workflow-connectors/v2/pkg/…`. The release workflow now refuses a tag whose major version does not match the module path.
- **Breaking: `storage.ProviderClient.Fetch` takes `maxBytes`.** The core passes 1 MiB for an inline fetch and 50 MiB for a document, so an inline fetch of a large object is refused from its size (`shared.ErrTooLarge`) instead of being read into memory first.
- **Breaking: an upload creates a document ref only with `createDocument: true`** (as fetch does). Previously every literal upload with a document-ref service configured also copied the bytes into the document store and could fail after the real upload had succeeded.
- **Every connector error is classified transient, permanent or unknown (OQ-9 resolved).** New `connectors.ClassOf`, `IsTransient`, `IsPermanent` and `connectors.DecideRetry(type, err, method)` → `RetryDecision{Retry, Class, Reason, Policy, Rule}` with `LogAttrs()` for the worker's log line and metric labels. Each provider integration attaches the class: S3/AWS error codes (`NoSuchKey`, `AccessDenied`, `InvalidBucketName` permanent; `SlowDown`, `RequestTimeout`, `InternalError`, `ServiceUnavailable` transient), HTTP status (408/425/429/500/502/503/504 transient; 3xx and other 4xx permanent; other 5xx unknown), network failures (timeouts, DNS, refused, reset transient; cancellation unknown), gocloud codes for Azure and GCS, Drive reasons (rate-limit 403s transient; ownership lost and upload in progress transient), document resolution (`ErrNotFound`, `ErrSourceMissing`, `ErrIntegrityViolation` permanent; read timeouts and a full or unconfirmed Valkey (`docref.ErrUnavailable`) transient), and send-email outcomes. Reference for workflow authors and operators: `docs/runbooks/retry-semantics.md`.
- **Breaking (retry behaviour):** `ErrUpstream` alone no longer means retryable. `IsRetryable`/`AutoRetryAllowed` now allow only transient errors; an unknown (unclassified) error is not retried automatically. `AutoRetryAllowed` is kept and equals `DecideRetry(...).Retry`.
- **`send-email` retry policy is now `not-delivered` (was `unsafe`).** A transient failure the provider provably never accepted (DNS failure, connection refused or connect timeout, 429/408, an AWS throttling code) is retried automatically, since a retry cannot duplicate the message. Permanent rejections and every `unknown` outcome are still never retried. A provider error code now takes precedence over the bare status when classifying a send. A send intent whose last outcome was `not_delivered` is re-reserved without `resend` (atomically; one of concurrent retries proceeds), so an automatic retry with a `messageKey` is not rejected as a duplicate.
- **Document refs are now shared and durable: content in S3, reference metadata in Valkey (OQ-1 resolved).** Refs used to live in worker memory: a ref minted on one replica did not resolve on another, and a restart lost every ref. New `pkg/connectors/docref`: `Service` (`Create`, `Open` (streaming), `Read`, `Delete`) over a `ContentStore` and a `Store` port. **S3 is the system of record for content** — `docref/s3content` writes each document to the platform's document bucket at `<prefix><tenant_id>/<uuid>` with the worker's own S3 client. **Valkey holds only the reference** — `docref/valkeystore` (go-redis v9.22.0) keeps a hash at `docref:{uuid}` with `reference_id`, `tenant_id`, `bucket`, `object_key`, `content_type`, `size`, `sha256`, `created_at`, `updated_at` and no content, so Valkey memory is O(refs), not O(document size). Writes are create-only (atomic Lua script), confirmed in the AOF (`WAITAOF`), 24 h key TTL. Every resolution checks the tenant (and that the object key is under the tenant's prefix) before calling S3, then verifies size and SHA-256: `docref.ErrNotFound`, `ErrSourceMissing`, `ErrIntegrityViolation` — `ErrValidation` to the workflow, and nothing is sent or uploaded. `valkeystore.CheckDurability` refuses a Valkey without AOF or with an eviction policy; `s3content.Store.Check` verifies the bucket. Operations: `docs/runbooks/document-refs.md`.
- **Breaking:** `shared.DocRefStore` is removed. `storage.New`/`sendemail.New` take a `*docref.Service`; `connectors.Config` gains `DocRefs *docref.Service` (production: `docref.NewService(valkeystore.New(...), s3content.New(...))`).
- Multi-replica integration tests (`test/integration/multireplica`): separate worker replicas, each with its own Valkey and S3 clients, on one Valkey and one document bucket — write on A/read on B, writer terminating after the write, rolling deployment, concurrent writers, concurrent create of one ID, delete and recreate, missing ref, tenant isolation.
- **Email delivery semantics are explicit and enforced.** `send-email` is documented (registry, README, ARCHITECTURE, LLD §5.4.2a, `docs/runbooks/email-delivery.md`) as not idempotent: at-most-once when not retried, effectively at-least-once when retried after an uncertain outcome, never exactly-once. Every failed send is now `ErrNotDelivered` (definitive: 4xx, or the request never left) or `ErrDeliveryUnknown` (ambiguous: timeout, reset, 5xx, crash) — **no longer `ErrUpstream`**, so no retry rule keyed on `ErrUpstream` can resend it. `*sendemail.SendError` gives outcome, provider and HTTP status; the output map carries `deliveryOutcome` (`accepted`/`not_delivered`/`unknown`) on success and failure.
- **`connectors.AutoRetryAllowed(type, err, method)`** (new) — the gate for automatic retries; since the classification change it equals `connectors.DecideRetry(...).Retry` (below). Also `connectors.IsRetryable`, `ErrNotDelivered`, `ErrDeliveryUnknown` and the `deliveryOutcome` output.
- **Optional duplicate-request protection** for `send-email`: new `messageKey` and `resend` inputs, `sendIntentId` output, `connectors.Config.SendIntents`, packages `pkg/connectors/sendintent` and `sendintent/sqlstore` (platform-pgcommon, `connector_send_intents`, `ApplySchema`). A second request with the same key is rejected before sending; `resend: true` is the explicit opt-in. This is not idempotency.
- `sendemail.New` takes options (`sendemail.WithSendIntents`).
- **Drive uploads can no longer create duplicate files.** Drive has no atomic create-if-absent, so two concurrent uploads of one name could both create a file. A new document registry is now the uniqueness authority: `pkg/connectors/documents` (`Store` port; `PENDING_UPLOAD` → `UPLOADING` → `AVAILABLE`/`FAILED`, plus `DELETING`; `MemoryStore`) and `pkg/connectors/documents/sqlstore` (PostgreSQL; `uq_connector_documents_identity` on tenant + provider + folder + filename, owner/lease compare-and-set, `connector_document_attempts` audit table). The store is built on **platform-pgcommon v2** like every other service's database access: it runs on the worker's `*pgcommon.Pool` (`pool.WithConn`, `pgcommon.RunInTx`), and its golang-migrate migrations are applied with `sqlstore.ApplySchema(ctx, runner)` — the `outbox.ApplySchema` pattern — tracked in `connector_documents_migrations`. Only the call that claims the row writes to Drive; a concurrent upload of the same document gets a retryable `documents.ErrUploadInProgress` (`*InProgressError` with the document ID) and never touches Drive; a re-upload or a retry of a `FAILED` row replaces the same Drive file in place. Files are addressed by the recorded Drive file ID and tagged `appProperties.connectorDocumentId`, so a retry after a crash adopts the file instead of creating another.
- **Breaking (worker wiring):** `googledrive.NewProvider` now takes the store — `googledrive.NewProvider(sqlstore.New(pool))` — and every Drive call needs `connectors.WithTenant(ctx, tenantID)` (new; `ErrMissingTenant` without it). Run `sqlstore.ApplySchema(ctx, runner)` in the worker's migration step. The worker needs platform-pgcommon **v2** (`execution_service` is on v1 today — see LLD OQ-14).
- Tests: the Drive race scenarios and the store contract suite run against the in-memory store and PostgreSQL under `-race`; Integration infrastructure is defined once in `docker-compose.yml` (PostgreSQL 17, PgBouncer v1.25.2 in transaction mode, Valkey 8 with `--appendonly yes --appendfsync always --maxmemory-policy noeviction`, floci 2.1.0 S3 with an init hook creating the dev document bucket and its 2-day lifecycle rule) and used by `make docker-up`/`docker-down`, the postgres and integration test suites, and `validate-test.yml` (`docker compose up -d --wait`). Document refs are tested against real Valkey and S3: the multi-replica suite (write on A/read on B, writer restart, rolling deployment, concurrent writes, concurrent create of one ID, delete and recreate, missing ref, tenant isolation), missing and overwritten objects, a 48 MiB streamed resolution, concurrent resolution, metadata-only hashes, and Valkey restarts after which documents still resolve from S3. CI downloads platform-pgcommon with the org-level `GO_PRIVATE_TOKEN` secret, configured exactly as iam-org-membership does ("Configure private module access" git credential, `GOPRIVATE`/`GONOSUMDB` on the download step, `secrets: inherit` from `ci.yml`/`release.yml`), and every checkout uses `CI_REPO_READ_TOKEN || github.token`. Unlike iam-org-membership's `release.yml`, the release workflow also passes secrets to its validate jobs and configures module access in its build job, which a private dependency needs.
- **Cached provider clients have reference-counted lifetimes.** `shared.ClientCache` replaces the per-connector map in `storage` and `send-email`: each call holds a handle for its duration, a cache overflow or the new `ResetClients()` retires entries, and a retired client is closed (via `io.Closer`) exactly once after its last call finishes — never under a running call. Previously retired clients were dropped without closing. gocloud closes its bucket and its own S3 transport; SES, Gmail and Graph drop idle connections. Coverage gate raised to 83%.
- **`chat-notify` and `document-extract` no longer fall back to the in-memory mock.** With no provider client every call fails with `ErrValidation`, so a chat task never reports a message as sent when nothing was sent. Set `Config.ChatNotifyClient`; tests pass the mock explicitly.
- **Numeric path and query parameters are sent as plain numbers.** JSON numbers decode as `float64`, and `1234567` was sent as `1.234567e+06`.
- **Inline storage content survives JSON.** A fetched object that is not valid UTF-8 is returned base64-encoded with a new `contentEncoding` output (`utf-8`/`base64`); upload accepts a matching `contentEncoding` input. Inline fetch is limited to 1 MiB — set `createDocument` above that.
- **An upload can return a `contentRef`** that a later task can attach or re-upload — with `createDocument: true` (see the opt-in entry above); an upload whose content is a ref returns that ref.
- **Size limits:** objects 50 MiB, internal responses 10 MiB, email attachments 25 MiB in total; over a limit is `ErrValidation` (and `shared.ErrTooLarge`).
- **Timeouts:** every internal call is bounded by its alias `timeout`, else 30 seconds (`shared.CallTimeout`); Gmail, Graph and GCS OAuth token requests use a 30-second client on a background context.
- **Error classes:** `shared.Classify` keeps a provider's `ErrValidation` (a missing or invalid credential is no longer `ErrUpstream`) and keeps the original error in the chain for `errors.As`. An unknown alias is `ErrValidation` (still matching `aliasconfig.ErrUnknownAlias`); a transport failure is `ErrUpstream`; `sql-query` checks the status before decoding.
- **`region` is required for `aws-s3`.** `projectId` is optional for `gcp-gcs` (it was never read). The storage description no longer says "S3-compatible".
- **SES `From` display names are encoded** with `net/mail`, so a comma or non-ASCII name no longer breaks the address.
- **Gmail MIME:** quoted-printable body with `Content-Transfer-Encoding`, and attachment base64 wrapped at 76 characters (RFC 2045, RFC 5322 line limit).
- **`aliasconfig.Validate` rejects a `baseURL`** that is not an `http`/`https` URL with a host and no userinfo.
- Regression tests for every item above; the coverage gate is a ratchet (now 98%, 99.96% measured).

  This move by itself changed no other API (`ProviderConstructor`, `EmailMessage`, the mocks and the connectors' inputs/outputs); the `Config` additions are listed above.

### Fixed

- **Registry covers every field the connectors use.** `storage` gains the `contentType` input (upload; it defaults to a ref's own content type), and `send-email` gains the `sendIntentWarning` output (set when the outcome could not be recorded). The connectors already read and returned both, but definition_service validates authored workflows against the registry, so neither could be authored or mapped. A registry test pins both.
- **A `rest-call` error status is classified by the status alone.** An oversized or cut-off error body no longer turns a transient 503 into a permanent `ErrValidation` or upstream read error.
- **Docs no longer claim a nil `Config.HTTPClient` has a 30 s client timeout.** Each call is bounded by its alias `timeout`, else 30 s. The dependency rules in ARCHITECTURE now match `.go-arch-lint.yml`.
- **A lost reply on a document-ref write no longer becomes `ErrExists`.** When Valkey applied the write but the connection dropped before the reply, go-redis's own retry used to fail with `docref.ErrExists` for a ref that was in fact stored; it now succeeds.
- **The document-refs runbook describes failover accurately.** `WAITAOF 1 0` confirms the primary's AOF only, so an acknowledged ref can be lost on primary failover. The consuming step then fails permanently with DocumentReferenceNotFound and nothing re-runs it; the runbook gives the operator steps.
- **A reservation whose reply was lost goes ahead once.** When the reservation committed but its reply was lost, `send-email` recognises it by its token and sends once, instead of leaving the key pending.
- **SES templated sends include attachments.**
- **Gmail rate limits are retried.** A 403 with `rateLimitExceeded` or `userRateLimitExceeded` is a transient not-delivered failure.
- **Every `send-email` failure output carries `deliveryOutcome`**, including validation failures, a document-ref outage and an intent-store failure.
- **A partly written request is never `not_delivered`.** A request that failed after the transport began writing it, even part-way, is classified `unknown`.
- **Drive no longer duplicates a hand-placed file.** An upload over a hand-placed file used to leave two files with the same name, and after a delete a fetch returned the stale hand-placed content.
- **Drive releases its registry row after a failure.** If the registry failed after a successful claim (Advance or Remove), the row stayed busy and retries got `InProgressError` for up to 15 minutes. The row is now released, and a delete retried after a failed Remove succeeds.
- **Drive registry writes after a Drive call are bounded.** Complete, Fail and Remove run detached from caller cancellation but bounded by 10 s; before, they could hang on an unreachable database.
- **Statement and lock timeouts bound every store call.** pgcommon applies `StatementTimeout` and `LockTimeout` (`PG_STATEMENT_TIMEOUT` / `PG_LOCK_TIMEOUT`) only to transactions it opens. The document-registry and send-intent stores ran their single statements through `Pool.WithConn` and so had no timeout: a statement waiting on a row lock or running slowly held its connection until the caller's context ended. Both stores now run every statement in `pgcommon.RunInTx`, directly and behind PgBouncer. Tests hold a row lock or slow a statement and check that the call fails fast with a transient error; they fail against the previous code. pgcommon v2.0.1's own fix covers only `WithConn`'s PgBouncer wrapping transaction, which needs an identity in the context, so it alone would not have reached these calls.
- **The document claim is one statement.** `documents/sqlstore` `Claim` is a single `INSERT … ON CONFLICT DO UPDATE … WHERE` (insert, or take over an idle or expired row) instead of an insert followed by a separate takeover, so a concurrent delete can no longer fall between the two.
- **LLD corrections.** The `ProviderClient.Fetch` signature includes `maxBytes`, and the retention text describes S3 content plus Valkey metadata instead of PostgreSQL plus `Prune`.
- **Drive errors at the upload, fetch and delete call sites were class unknown**, so a rate-limited Drive call (403 `rateLimitExceeded`) was never retried and a 404 was not permanent; they now go through the Drive classifier.
- **`s3content.Check` failed under the documented IAM policy**: its probe read outside the document prefix (AccessDenied). It now probes under the prefix it is given.
- **A late outcome of a superseded send attempt could overwrite a newer, in-flight attempt** and re-open the key for an automatic retry — a duplicate email. Outcomes are now recorded per attempt, and recording is bounded to 10 s so a stuck database cannot hold a call after the email was accepted.
- **Valkey:** reads and deletes go to the key's master (a replica-reading client could report a fresh ref missing — a permanent failure); cluster redirects (`MOVED`, `ASK`, `TRYAGAIN`, `CLUSTERDOWN`, `LOADING`) are transient and reload the slot map; `WaitAOFTimeout` is clamped below the client's read timeout.
- **Email OAuth token failures** are classed by the token endpoint's status (400/401 permanent, 429/5xx transient; unreachable transient) instead of unknown.
- **Drive:** the lease budget is measured from the claim, and deletes are bounded by it too.
- **Internal calls:** an alias timeout above 30 s was silently cut to 30 s; every call now has its own deadline (`shared.CallTimeout`) and the default client no client-wide cap.
- Tenant IDs with invalid UTF-8, control characters or more than 255 bytes are refused (`docref.ErrInvalidTenant`); `docref.NewMemoryStoreWithTTL(0)` means the 24 h default, as for Valkey.
- **CI:** Trivy skips `tools/` (lint-only dependencies no longer gate releases or enter the SBOM); `make tidy-check` checks both `go.mod` files in CI, `make ci` and the pre-commit hook (it found `tools/go.sum` drift); stale diagrams and LLD rows corrected; LLD OQ-5 resolved.
- **CI:** docs-only changes run the pipeline again (a workflow-level `paths-ignore` skipped the run, so required checks never reported and docs-only PRs could not merge); the release CVE gate includes `UNKNOWN` like CI's; the golangci-lint test-file exclusion moved to v2's `linters.exclusions` (the old key was ignored); golangci-lint lives in `tools/go.mod` so its ~200 dependencies no longer enter consumers' module graphs; compose and test images are pinned by digest; `pkgsite` is pinned.
- **Valkey durability confirmation used the wrong connection.** `WAITAOF` confirms only the writes made on its own connection, but the ref write and the `WAITAOF` went out as two commands on a pooled client — under load the confirmation could run elsewhere and confirm nothing, so a ref could be reported durable and lost in a crash. Both now go out as one pipeline on the key's node (its master on a cluster).
- **A managed Valkey with CONFIG blocked and AOF off was accepted at startup**, then failed every write: `CheckDurability` now probes `WAITAOF` first, on every master.
- **Email: a connect timeout was reported `unknown`** (Go returns the context error, not a dial error), so a send that never left was not retried, contrary to the runbooks; and a TLS record error after the request was written counted as "nothing sent". Adapters now trace whether the request was written (`sendemail.TraceWrites`, `ClassifyAfterSend`): not written → `not_delivered`, written → `unknown`.
- **A send whose outcome could not be recorded on its send intent** left the intent `pending`, so the automatic retry it invited was refused as a duplicate and the email silently never sent. Such a failure is now class unknown (no automatic retry) with a reason saying to verify and resend.
- **Drive: a write could outlive its lease** and race a takeover into a second file that delete never removed. The write is now cut off before the lease expires; a create removes other files tagged with the same document, and delete removes every tagged file. A completion that cannot be recorded releases the row at once instead of after the lease.
- **S3: any 404 counted as a missing document**, including a missing bucket; only `NoSuchKey` does now.
- **Document refs:** a malformed reference ID is `ErrNotFound` without a lookup; a stored record with a negative size or malformed checksum, or a Valkey hash the store could not have written, is `ErrIntegrityViolation` (previously a possible panic, or a retried error); `Read` looks the reference up once; the cleanup after a failed create is bounded (10 s).
- **The client cache retired all 256 entries at once** when full; it now evicts the least recently used one.

### Fixed

- `docRefStore` was owned per-connector-instance, constructed fresh inside `newStorage` — a doc ref minted by `storage`'s fetch (`createDocument: true`) was never resolvable by any other connector, silently breaking `send-email.attachments`' documented "list of document refs" contract. `connectors.New()` now constructs one `docRefStore` shared by `storage` and `send-email`.
- `storage`'s `provider` field description still said "Defaults to aws-s3 when omitted" — stale since Decision #20 removed the default entirely.
- `chat-notify.visibility` shipped as an enum field with no `EnumValues` — would have rendered as an empty dropdown to any UI consumer of `/connectors/registry`. Now `public`/`private`, matching `design/LLD/workflow_connectors.md` §6.4.6 (rev 7.2).
- `document-extract.confidence` was a single scalar float; the LLD's own "per-field confidence" wording means it needs to be keyed by field name — now `FieldKindMap`.
- `registry.All()`/`connectors.New()` silently overwrote a map entry on a duplicate `Type` (e.g. a copy-paste bug reusing a type constant); both now panic loudly instead.
- Per-field registry tests added (`Name`/`Kind`/`Required`/`EnumValues` for all 6 types) — aggregate-count-only assertions had let the `visibility` bug above ship unnoticed.
- `send-email`/`document-extract`/`chat-notify` briefly had a `provider` field with zero real per-provider implementation behind it (a mock-only client for all providers) — removed until each ships real code, matching LLD Decision #20.
- `storageConnector` silently fell back to an in-memory mock for any unconfigured provider, and defaulted a missing `provider` to `aws-s3` — both removed; both are now `ErrValidation`.
- **`send-email`'s client cache could silently impersonate the wrong mailbox for `google-workspace`.** `emailCacheKey` hashed provider + credential fields only, not `senderEmail` — but a `google-workspace` client binds one impersonated mailbox (`jwtConfig.Subject`) at construction time. The same `serviceAccountKey` sending as two different `senderEmail` values within the client cache's lifetime would reuse the first call's cached client for the second, silently sending as the wrong sender. `senderEmail` is now part of the cache key (LLD §10 Decision #23).
- **Email header injection via `buildRawMIME` (Gmail's raw-message path).** `senderName`/`receiverName`/`subject` — the latter two explicitly documented as typically sourced from workflow-instance data, i.e. end-user-submitted form input — were concatenated directly into RFC 2822 header lines with no CR/LF stripping; a value containing `\r\n` could inject arbitrary extra headers (e.g. a `Bcc:`) into the outgoing message. All fields feeding raw header lines are now stripped of embedded CR/LF before use. SendGrid/SES/Graph are unaffected — their SDKs build structured (JSON) requests, not raw header text.
- Graph's `sendMail` REST path built the request URL via unescaped string concatenation of `senderEmail`; now `url.PathEscape`d.
